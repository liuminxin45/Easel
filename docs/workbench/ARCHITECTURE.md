## 与 Easel 共用的核心

| 能力 | 共用入口 | 私有扩展的职责 |
|---|---|---|
| 对话界面 | 原 `ChatPage`、`MessageBubble`、问题卡片 | 输入草稿、准确技能选择、制作方案、版本与成品入口 |

| 原生会话身份 | 原 `harnesses.store.bind` | `outputs/_sessions` 下的真实绑定、服务器历史与可重读事件 |
| 项目技能 | `skills/builtin/*/SKILL.md` | YAML 内的能力声明、版本及冻结资源副本 |
| 平台连接 | Easel 账号驱动 | 真实账号实例、画像归属及各交付能力证据 |
| 数据采集 | fork 自定义 Python 采集器 | 来源快照、去重、入库、ack 及已有新闻增强合同 |

上游组件只增加默认不启用的通用端口，不反向引用 `easel_workbench`。原 `App.tsx`、普通 Easel 构建和默认行为保持可用。私有前端消费上游组件，服务器适配器位于 `easel_workbench/`，已有领域事务位于 `easel_workbench/runtime/`。没有第二套 Codex 原生传输用于新对话。

## 会话与作品是不同身份

新建对话先由服务器建立真实会话记录和项目下的元数据。首次发送由 Easel 在同一连接中完成 thread/start 和 turn/start；只有收到实际 turn/start 回执才记录为 running。连续对话沿原 session key 和 native binding 接续。

普通消息调用本地选题研究技能；通过 `/` 或 `+` 选择内容生产、写作或配图动作后，发送即冻结准确画像、材料、技能版本和完整指令，并使用同一请求身份直接提交，不再弹出只读制作方案确认。冻结凭据、会话受理和作品版本登记处于同一事务，忙碌拒绝不会留下孤立制作任务。完成后，对话产物和作品成品页可展开“制作参数”，按准确版本读取保存的画像、技能和指令；不以当前设置回填历史。一个会话可以关联贴图和文章作品，修改必须指定本会话内的准确父版，继承其画像和技能，另存新版本。原始反馈、批注和来源随该版冻结，不变为全局偏好。

对话受理、原生执行、成品接收和业务完成分别记录。`chat.py` 持有可重读事件，SSE 只订阅；断线不取消制作，重连不会发送第二个模型回合。停止通过原 Easel turn/interrupt；未知回执保留原标识，不能当成未发送。

成品只接收本回合明确列出的文件，并限定于准确 outputs 会话/回合目录。原文件保留，登记副本与 SHA 进入版本。过程记录、提示词和参考图不能冒充成品。模型完成并不证明可采纳，现有独立核验、原字保护和发布授权继续生效。

## 技能与程序事务

当前技能登记只在各项目 `SKILL.md` 的 YAML 中维护，不增加另一份实时 capabilities.json。`skills/workbench-import.json` 仅为复制来源和字节变换的审计记录。八个业务技能及必要资源均位于本项目，不安装到用户全局目录，不再实时读取 neo-content 的技能入口。

内容生产是实际可读、可调用的组合方法；写作、配图和独立检查均有准确版本。方法正文不写在 Python 分支中。`skills.py` 只定义适用任务、业务必选约束及启动动作；版本、账号、幂等、停止、采纳与交付是程序事务，不能交给模型自行解释。

`creator_skill_versions` 保存不可变发布版本，受理时把准确正文和资源字节冻结到 `outputs/_sessions/skill-inputs/<snapshot>/`，传给原 Codex runner。当前磁盘更新不能替换在途输入。候选不写当前 SKILL；明确发布和恢复版本经源码同步记录更新当前项目入口，失败时保持待核对，不冒称已同步。

新本地技能的独立核验、参考分析、经验整理及新闻增强也使用原 CodexAdapter 的只读执行端口，保留准确图片、输出合同、推理配置和实际回合回执。后台运行使用隔离的临时原生配置，关闭额外工具与 MCP；只提供既有访问令牌，临期时由原生 CLI 正常续期原登录，不复制刷新令牌。最终完整消息与流式说明分别保存，未知回执和无效结构化输出不重新调用模型。

拆解参考、经验整理、传播分析和独立核验仍先由业务服务提供准确证据/版本上下文，再调用所选技能。其结构化结果必须经原有候选或核验服务登记，不能把聊天里的一段输出当成已发布规则或核验事实。经验整理仍须用户按需发起，没有新增定时学习。

## 保留的业务差异

平台连接由私有账号服务管理会话与身份，实际扫码、身份查询及交付调用当前 `skills/shared/scripts/` 中的 Easel 脚本，随不可变后端冻结，不再调用迁入时的 vendor 副本或浏览器扩展。账号页直接列出公众号、视频号等平台；扫码会话保存在 `data/easel-accounts/<session>/profiles-<generation>/`，凭据仍由服务器加密保管，AppID 校验与浏览器扫码身份分别记录。

`EaselDistributionRuntime` 是生产唯一分发适配器，没有同步助手回退。旧桥接配置、扩展发现及人工检测接口退役，旧辅助页清除票据片段后转到账号页，新前端不再打包检测页。历史连接、凭据、批准和回执保留；明确重新扫码且身份一致时沿用原连接 ID 并增加修订，旧批准不能借新驱动自动恢复。官方尚无连接适配的历史平台继续只读保留。

交付仍必须来自既有准确版本、素材、账号和动作授权；登录成功不授予发布权限，首次能力只显示待试运行。发布前重查真实身份，视频号实际提交按键仅允许一次，超时不借上游恢复循环重复发送。仅结构化平台读回可以登记已核实结果；草稿建立回执、界面提示和子进程退出码都不能冒充远端核验。B站上传在准确分区及版权信息进入冻结渠道稿前保持未接入，账号扫码仍可用。

- 账号继续按真实账号实例管理，保留过期、身份不符、存草稿/发布/读回证据和未知回执；不退化成单个平台的一个布尔登录状态。
- 画像保留修订、版本化资产、准确技能 pins 和账号归属；不退化为未版本化的 persona 文本。
- 内容库由作品/版本/决定/交付台账驱动；不以扫描 outputs 目录代替采纳与发布事实。会话成品预览也读取该版本登记的文件 ID。
- 设置保持已有固定 Codex 与授权范围，不因复用上游而开放模型/权限任意切换或恢复已退役媒体设置。
- 旧作品深链、冻结任务和固定会话仅在兼容路径接续。旧准备失败的确切修复保留原输入和重试额度；历史错误不会因部署重新排队。

通知、通知设备、顶部通知/设置、旧自动账号检测和个人资料库继续退役。旧项目原件、历史版本和授权证据保留。

## 验证与上线

原生候选由 `native-releases/` 提供，后端、项目技能和 workspace 指令由不可变 `workbench-releases/` 共同冻结并绑定 SHA。上线先验证准确候选、业务合同、真实 Windows 浏览器和模拟移动端；实际原生 CLI 的零模型检查与模拟制作分开记录，不冒称真实 AI 质量或实体 vivo 通过。

切换必须在业务空闲、原生队列无未核对任务时进行。围栏停写和停止写入者后，按预览 SHA 事务性迁入本地技能发布版本，再原子切换绑定的前后端。保留同一权威数据库；不恢复旧库、不打断制作、不重放未知回执。最终版本、检查数量和证据以 `STATUS.md` 及 `.local/workbench-deployment` 的实际切换回执为准。
