# Easel 私有工作流扩展

## 目标与边界

主工程位于 `D:/Projects/Easel`，基线为本地 fork 的
`514caf8089f89b4793063aeae867690cc69bf8b8`，官方共同基线为
`5a597e5f3ef5b01098b53f36caf719dd9a32b7bf`。
保留该 fork 的自定义 Python 数据源协议，不回退到官方较早的热点实现。

上游继续拥有 `easel/`、原 `web/frontend/src/App.tsx`、标准技能及组件。
私有业务在 `easel_workbench/`，前端在 `web/frontend/src/workbench/`。
前端直接复用上游样式、图标及选择控件；普通 Easel 构建与私有工作台构建分开。
业务迁移必须先保持现有作品、版本、账号、明确交付授权及未知回执合同。
不因引入底座而开放通用模型切换、自动发布、媒体制作或已退役页面。

## 兼容服务

`runtime/` 从当前正式不可变包迁入，不从有未提交更改的旧工作目录批量复制。
导入工具将内部依赖改为包内绝对导入，来源及导入后哈希见 `import-baseline.json`。
它是待逐领域收敛的兼容层，不宣称已经替换为官方 Codex 执行器。
现有冻结输入、原始反馈、原生会话、operation_id 和未知回执不可重建或重放。

## 数据与上线门禁

正式服务与业务数据已迁入Easel，旧服务写入者已停止；实际版本和证据见 STATUS.md。
数据迁移须采用 SQLite backup、一致性检查、文件 SHA 核验和来源记录。
切换必须排空已知在途制作、采集和交付，核对每个进程身份，确保只有一组写入者。
回退需要保留切换后产生的业务状态，不能恢复旧库或重新发送未知任务。
浏览器继续使用原 HTTPS origin、草稿键、附件数据库及操作标识。

## 验证

前端 `npm run check:workbench` 使用 TypeScript strict。
`npm run build:workbench` 在 Node 24.19.0 下生成独立不可变 native 候选。
候选通过不等于已上线。当前正式版本已通过领域合同、实际候选浏览器、数据及故障恢复验收，后续变更仍须绑定准确快照。
