# 修复重新进入会话时残留的中断提示（2026-11-01）

用户明确反馈「进入会话就看到」原生中断技术提示。上一批仅覆盖终态回执的展示；新复核确认，显式停止清除了 pending/running，但未清内存中的 error/feedback，同一工作台客户端返回会话会复用该 Runtime。另一个入口会对浏览器保留的旧 pending 先重新订阅事件流，即便本次已读回同一回合的服务器中断终态。

本批在私有 `chatRuntime.ts` 与 `ChatSessionView.tsx` 修复生命周期：

- 显式停止只有收到 `stopped:true` 才清旧错误与反馈；未确认或认证代际变化仍保留原状态。
- 进入会话时先使用已有的准确版本恢复校验，必须满足原会话、作品、版本、画像、技能及服务器 `can_continue`，且服务器没有 pending。
- 只退役同一 saved/active turn 的本地运行者、计时器、流和旧 pending，随后自动恢复逻辑看到 completed 就跳过。迟到 SSE/回执回调因原拥有者失效，不能复活旧状态。
- 只清除与服务器历史业务错误精确相等的错误；独立 hook 错误、不同任务、unknown 或未获授权的记录保持。草稿文字、附件和技能选择不经过重新确认/清空流程，逐字保留。
