# 移动端私有扩展交互统一

官方基线：`5a597e5f3ef5b01098b53f36caf719dd9a32b7bf`。

## 问题与目标

历史制作中断被持续放在会话顶部，容易被理解为当前连接故障。各私有扩展
直接使用未统一呈现的 details/summary，技术记录与操作按钮挤在正文中。

共通 UI 继续由原 Easel 页面、消息组件、产物画廊、文案组件和样式负责。
本批仅统一私有业务的呈现与宿主接缝，不引入第二套设计框架。

## 实现边界

- `ExtensionDetails` 为私有短详情保留原生键盘语义、受控 open/onToggle 和
  懒加载时机，统一整行 44px 触控范围与 SVG 箭头。
- `TextRecord`、`JsonDetails` 使用原私有 `Modal` 展示长记录，复用导航层、
  Escape、返回和焦点恢复。只让内容体滚动；移动端长记录靠底展示。
- `TaskStatus` 仅展示对应消息/版本的历史结果。会话顶部的 Notice 仍显示
  当前错误，正常轮询不增加刷新提示或重排布局。
- `ChatSessionView` 在消息扩展槽展示中断状态。继续制作需要服务器确认的
  原 work/version/session/profile 和空闲状态；正在接续的同版本不再重复
  给出继续按钮。新闻来源与版本上下文移至输入附近的可展开入口。
- 完成版的修改入口与作品页共享 `lib/workChatPath.ts`。读取准确版本后使用
  navigation ticket 完成导航，用户已离开时不抢回页面。
- 采纳复用 Completion；不采纳仍须确认，并提交原 work/version 的决定。
  保留原字原因。编辑仅导航，继续仅预填，均不自动开始制作。
- 只为助手消息读取产物，避免用户消息 ID 引发无效 400 和重复轮询。
- 官方组件与官方样式未改；扩展 CSS 仅限定在 `.ew-*` 所有者内。

## 页面迁移

会话、作品及制作参数、画像素材/技能/账号、技能版本/经验、发布交付记录、
使用统计均使用同一详情组件。完整历史、原始回执、冻结指令与 SHA 仍可查，
不改写历史数据或扩大采纳、发布权限。

## 验收方式

使用冻结前端与活动冻结后端，在 TEMP 数据库和真实 Windows Edge 中验证：

1. 全页面矩阵按覆盖清单检查路由、详情与弹窗，含窄屏、桌面和明暗主题。
2. 中断/未知回执/离开后返回验证原草稿和附件、准确版本及不重放。
3. 触控滚动、详情键盘操作、长记录单滚动、关闭重开与焦点恢复。
4. 自动采集本地 RSS → 保存选题 → 合成贴图 → 拒绝 → 修改新版本 →
   合成独立检查 → 采纳并归档，核验真实临时文件字节及原始来源。
5. 原 Easel 独立构建、私有构建、架构检查、技能策略与前端回归。

TEMP 推理和独立检查为合成执行，不证明真实模型质量、平台发布或实体 vivo
WebToApp 的设备行为。正式部署只切换经过验收的前端，不重启后端工作进程。

## 后续同步方式

优先扩展槽与适配器；已有控件直接引用原实现。新的私有交互先复用上述共享
组件，再决定是否增加单个通用组件，不在每个页面重复拼装。确需修改官方
共通组件时单独提交、说明必要性，保持差异可核对。代码只推送自有 fork。

验证结果和发布绑定在最终交付时补充。
