# 移动端返回、状态恢复与交互审计

## 结论与核对范围

普通页内返回应先恢复刚才的列表、筛选、位置和输入；必要时在后台重新核对数据，不应每次回到空页面
再等一轮加载。切换到外部网页、安卓回收WebView进程或真正刷新后，需要重新读取服务器数据是另一类场景。

已核对当前main `dad9e47a98bf91bd964bc0a5b6f8905690dfded3`，运行前端
`native-official-shell-r6-20261102211844`全部159个构建输入与当前源码一致；后端
`workbench-20261102-152349`。本轮只做审计，没有修改应用源码、业务数据或部署。

本轮列出18项源码缺口/体验风险。其中6个机制用真实TypeScript模块与隔离依赖受控复现；
其余为源码支持的路径分析，不冒充vivo/WebToApp上的逐项实测，也不声称已经发现全部设备问题。
证据在`.local/workbench-validation/mobile-navigation-audit-20261102/`：
`audit.mjs`、`controlled-evidence.json`、`source-binding.json`。

## 为什么返回会重新加载

1. `EaselWorkbench`按当前路由切换页面组件，离开的页面会卸载。
2. 官方页面挂载时的effect重新读取数据；列表、筛选、目录等多数状态仍属于组件自己的useState。
3. `bindWorkbenchNativeApi`的GET走`client.api.get`，绕过已经实现的`client.read`缓存、请求合并和条件请求。
4. 原有NavigationService虽然保存位置，但默认标记的是外层page-host，实际滚动常在内部page-scroll等区域。
5. 热点恢复还在等待contentReady；当前NativeNews/NativeTrends没有调用它。

因此只增大缓存时间，或只给页面加keep-alive，都不能完整解决问题。主要缺口在私有宿主适配，
少数行为来自官方原页面；不需要重写官方页面或另建移动端壳。

## 实施方案：继续使用Easel作为基座

不另建移动页面、导航组件或弹窗库。优先复用WorkbenchClient、NavigationService、DraftRepository、
SessionRuntime、现有Drawer与官方页面。统一接缝放在宿主层；必须改公共组件时只增加通用数据/视图状态/
就绪/生命周期端口，原入口保持默认行为，不引入私有模块依赖。

数据快照与视图状态分离：服务器业务数据只在有界内存缓存，不新增localStorage/IndexedDB作品缓存；
URL/历史条目只保存筛选、目录路径、消息锚点等必要UI元数据；输入和附件沿用已获准的原草稿仓库。
账号/画像/授权会话变化必须隔离缓存；401清除私有读缓存，继续保留获准草稿与操作身份。

按三个批次落地，各批都有独立验收及自有fork提交：

1. **返回即恢复**：M01、M02、M03、M04、M05、M10、M17。先选热点→原文→返回和内容库→文件→返回作
   代表路径，接通数据快照、ViewState、真实滚动容器与就绪信号，再扩展到其他模块。
2. **请求与生命周期收拢**：M06、M07、M08、M09、M13、M14、M18。合并版本探测、去掉重复失效、统一
   前后台调度，收紧会话查询与输入广播。服务器任务继续运行，客户端恢复只核对原身份。
3. **返回边界与反馈**：M11、M12、M15、M16。核对所有弹层和外链、离线错误、断点与真机键盘行为。

不要一次让所有页面永久挂载。若个别重页面需要保留组件，只做有上限的保活，并明确暂停其轮询、焦点和弹层，
不能为省一次GET保留隐藏页面持续运行。

## 验收应改成真实使用路径

- 同一数据/筛选下“列表→详情→系统返回”多次：新鲜缓存期无重复列表GET，过期最多一轮后台核对；
  页面不先清空，主列表与卡片位置恢复，筛选/目录/搜索/月份保留。真正被系统回收后允许从服务器重建。
- 让请求乱序、断网或超时：晚响应不得抢页面或恢复错位置；有旧数据仍可读，初读失败不伪装空数据。
- 打开每个弹窗/二维码/侧栏/画笔/下拉后Back：先关闭最上层，页面和输入不丢；输入法优先级在实体设备复验。
- 聊天查看旧消息时收到token/轮询：不被拉到底；原来在底部时正常跟随；返回会话恢复消息锚点。
- 连续输入100次：不按每键检查版本；普通情况下版本请求遵守统一最小间隔。检查帧耗时和草稿保存时延，
  不用截图替代性能数据，也不靠延迟保存来牺牲原件。
- 后台5分钟：非必要读取停止；切回后合并校验，未知回执0重发、任务0重新创建、配置/账号状态从服务器核对。
- CI补接入层和端到端请求数量/位置断言；既有纯缓存单测和布局截图没有覆盖“原页面是否实际使用缓存”。
- 实体vivo/WebToApp另测：系统Back/手势、WebView被回收、锁屏恢复、键盘/中文输入法、横竖屏、
  原生文件选择/下载/复制、Tailscale切网和长时间断线。本轮没有这些设备结果，不写成已通过。

现有正确能力继续保持：资源缓存、身份隔离、草稿与附件保存、navigation ticket、应用级会话执行、
统一抽屉和未知回执不重放均已有实现。此次方案是补齐接线和覆盖缺口，不是另造一套工作台。
