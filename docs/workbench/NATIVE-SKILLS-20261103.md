# 技能回归 Easel 原生流程

用户已明确选择：保留业务 SKILL，完全采用 Easel 技能执行流程；能力通过工作流和 SKILL 自身组织，不再维护私有技能管理与制作编排。

## 当前实现

- 技能页直接渲染原 SkillPage，其内部使用原 SkillDrawer。删除私有目录替换、抽屉替换、页头经验按钮、项目动作选择、制作确认、版本与试用、候选编辑和发布等入口；同时删除已无调用方的共享注入端口。
- 列表、详情、配置、执行共用官方处理逻辑。web/app.py 只保留必要的请求模型与路由包装，实际函数由 easel/web_services/skills.py 同一实现供两种入口使用。私有宿主只提供鉴权、配置与画像存储、原生引擎和持久请求身份。
- 普通聊天和技能执行不再调用私有动作解析、计划生成、版本发布指针、候选试用或模型调用登记。HTTP技能入口使用原生非交互执行语义；聊天中的交互继续由原 ChatPage 和原引擎处理。
- 原抽屉配置保存不需要新的控件：宿主透明绑定详情取得的配置修订，仍能拒绝过期保存。仅原生长任务的浏览器人工30秒截止时间取消，后端官方7200秒超时、外部取消和未知回执不重发保持有效。
- 七项项目业务技能的当前指令已调整为接受普通用户输入，读取所需参考、组合子技能、使用官方输出目录和 manifest 工作流。历史版本与资源仍留在数据库、不可变发布包及本次源码归档中；兼容元数据不再决定当前技能是否可调用。

## 经验功能退役与历史兼容

当前 experience-distillation 技能原件已归档并移出 builtin。新建经验整理、技能候选、试用、发布、回退、源码同步、私有画像技能绑定等请求返回410。原操作身份已经存在时只读准确原回执，不重新同步文件、不启动任务。旧管理链接回到原生技能列表，不挂载隐藏弹窗。

切换期间以准确预览 SHA 新增画像修订，清除 learning 默认项和所有私有技能版本 pin；原画像历史、技能版本、任务、反馈及文件不删除。历史作品上的制作/修改入口仅把准确文本、来源和文件引用带入普通对话，用户发送后才运行，不伪造私有采纳或交付状态。

五套旧测试中专门创建私有计划后触发自动编排的原文，逐字节归档于 `docs/workbench/retired-tests/native-skills-20261103/`，附SHA与退役说明。有效的并发、原请求所有权、损坏拒绝、未知回执、历史只读等检查已用原生请求或历史数据夹具保留，不以恢复旧生产入口让测试通过。

## 稳定性与验证边界

每日独立 canary 改走原生技能，直接核对隔离目录内实际 PNG、操作水印和工具记录，不再要求伪造私有作品版本或产物表记录；种子不再导出全部技能版本和资源 blob。每日一次限制、旧未知回执和已运行记录保持，本次不得再次触发当天真实模型任务。

验证与配对上线证据集中在 `.local/workbench-validation/native-skills-only-20261103/`。后续补记实际源码/配对版本、迁移结果与线上验证；TEMP假引擎不代表真实模型质量，模拟移动视口不代表实体vivo验收。
