## 修复内容

执行前拒绝曾被当作回执未知；旧全局 `chat:create` 长期 waiting 又阻止后续新建。恢复读取完成后未重新接回草稿与页面导航，也会留下“正在打开原生对话”。这些是已复现缺陷；没有取得原手机操作 ID，不能断言其最初由哪次断网或部署触发。

会话创建 opt-in 协议 2 明确区分未受理、受理中、完成和未知。受理元数据持久化，完成会话与回执同事务；慢请求返回 202，HTTP 断开不撤销工作，重启只恢复元数据，不调用模型。文件投影失败不再将已创建会话变成失败。

前端每次新建保存独立意图、原请求和操作身份；完成后先保存会话身份，再清 pending、幂等应用原草稿与导航。未知只核对原回执，不重新发送；明确未受理只允许一次同身份自动重试。旧操作使用独立 resolve 事务：找到已创建会话或封存准确旧命令，迟到旧 POST 不能再创建。新输入不猜测归属旧会话，恢复不自动制作或发布。

800ms 内的短等待不闪提示；异常和较慢状态使用页面主体卡片，30秒后停止持续旋转，提供检查、返回与详情。无重复顶部纯文本条。扩展 CSS 限定私有区域；按钮最小44px，窄屏保留16px边距。详情进入原 Drawer，不新增弹窗外壳。

R1 冻结验收实际发现关闭后重开仍保留旧 navigation ticket：服务器创建成功、页面 ready，但不跳转。R2 仅在当前路由明确拥有同一 flow 时重绑定页面身份，用户离开时仍不抢导航；原失败证据保留。
