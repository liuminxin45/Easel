# Easel 完整技能库接入

本轮以项目现有 Easel 技能为主体：115 个原生技能保留原始 `SKILL.md`、脚本、资源与
相对依赖；原有 8 个工作台技能作为扩展。没有安装到全局，也没有把技能正文移进业务代码。

## 界面与调用

- 共用官方 `CAPABILITY_MENU`、画笔、搜索、技能详情与 ChatPage。保留“做内容 · 要成品”
  和“做运营 · 要动作”的完整现有分组、顺序及 113 个实际菜单能力；菜单外另有 2 个
  原生技能，放在对应类别的“其他内置技能”。原有贴图、文章等动作列入“工作台扩展”。
- 官方“视频产线 · 整片大片”本身是 `incoming` 预告，没有可执行的技能文件。
  保留预告并禁用执行，不生成虚假实现。其他 115 个有文件的原生技能均可显式选择。
- 选择仅带入输入，不自动发送。技能库详情沿用官方说明和动作面板，可创建准确的原生
  会话并带入技能。API 仅聊天模式仍不接受本机技能。
- 媒体配置标志使用官方共享模型注册代码读取。已配置仅表示存在配置，所有原生技能的
  真实服务自测状态保持 `not_tested`，不因迁入目录就声称已经验证模型或平台能力。

## 适配边界

`easel_workbench/upstream_skills.py` 负责读取、冻结和接收；`chat_business.py` 负责
把显式选择适配到已有 `ChatService`、原生 harness 和现有版本/文件表。不创建第二套模型
传输、全局技能目录或后台制作调度。官方组件只接收通用菜单数据，不导入私有业务模块。

原生执行采用通用 `native` 任务，不套用工作台贴图/文章 JSON 格式或生产方案。工作台
扩展继续保留精确作品版本、父版、画像、独立检查、反馈、采纳及交付授权合同。

目录查询只读，第一次明确受理某个原生技能时才在原受理事务中登记不可变版本与资源 blob。
源码修订 SHA 随显式选择送达；初次受理前源码改变即拒绝。已登记的旧版、已受理输入和
原操作回执继续使用原版本，不重解析当前磁盘目录。目录别名如 `skill-xhs-analyzer` /
frontmatter `redbook` 按官方目录身份保留。

生产读取活动不可变后端内的技能；不读取未经部署的工作区改动。完整原生技能与共享资源
按路径和 SHA 冻结，以保持跨技能相对链接及脚本导入。模型只获得所选方法正文和资源路径，
依赖保存在项目 `outputs/_sessions/skill-inputs/<snapshot>/`，没有把整套说明拼进正文。
完整文件与 SHA 清单另存为 `native-library.json`，输入只带所选入口和清单位置，
避免每次对话都重复传入数百项依赖路径。

原生产物只从准确本回合的 `outputs/<session>/<turn>/products/` 登记，校验 SHA 后保存
到原有鉴权文件库。聊天和内容库共用官方预览/下载组件，文件链接使用已登记 ID。
发布、账号修改和长期画像/技能更新仍需其准确授权；迁入技能不包含平台写入授权。

## 验证与发布证据

验证源和证据保存在 `.local/workbench-validation/upstream-skills-20261030/`。
仅将本轮技能改动叠加到已审核的设置/热点版本，其他任务尚未完成的改动不进入候选。
前端源码按其准确 `build-inputs.json` 验证；后端、技能与工作区说明由不可变 manifest 绑定。

合成制作使用 TEMP 数据和假 harness，确实经过受理事务、原生形状的执行请求、真实文件
写入、版本登记、预览与内容库。与真实 AI 质量、外部服务和实体手机验收分别记录。

正式切换沿用现有身份、空闲、原生队列、未知回执和停写围栏检查。保留上一候选，
不复制或恢复业务数据库，不重放原任务；实际版本和检查结果以本轮 acceptance/deployment
记录为准。
