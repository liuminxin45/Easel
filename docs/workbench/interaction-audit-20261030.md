## Easel 对照与原因

对照本地 `upstream/main` 的 `5a597e5f3ef5b01098b53f36caf719dd9a32b7bf`，读取原 `AccountsPage`、`SettingsPanel`、`HarnessSettings` 和 API 代码。原 Easel 在点击时先更新按钮或弹窗，服务器受理后结束提交，后续查询和长任务进度独立刷新。本次没有声称该本地引用是远程最新提交。

私有工作台原有问题包括：

- 把正常处理中、临时断连、未知回执统一交给红色错误组件，并要求用户“核对原操作”。
- 多处 action 在写入受理后继续等待整页读取；读取慢或失败会拖长按钮等待，甚至让已受理操作显示异常。
- 不同实体和动作共用操作范围；设置、账号和普通业务又各自维护恢复逻辑。
- 扫码受理前同步运行完整环境诊断；新闻来源更新筛选时关闭弹窗；统计接口多传字段且界面读取错误的配置字段。

## 输入、身份与恢复

- 保留原输入、附件、操作 ID、账号与准确版本；未知执行不重新 POST，不重新上传旧附件，不重建回合。
- 公共恢复只读取既有业务回执，没有新增业务事务日志。离开原页面仍会恢复；隐藏页面、退出和鉴权过期停止读取，返回并通过鉴权后继续。
- 原生对话通过原 session/turn 的 GET 恢复；已知仍在运行时接回原流。移除人工“核对原请求”按钮。
- 设置及账号凭据只在表单与本次请求中存在；浏览器恢复记录仅保留操作元数据和 SHA，旧设置待定记录保留原 ID 导入。
- 明确的 4xx 校验、版本冲突与拒绝继续显示真实原因。制作、采纳、归档、平台交付与冻结输入合同没有取消。
- 来源写入回执只包含与公开列表一致的展示字段，不返回请求头、URL 凭据或脚本路径。新增、启停、删除可以立即展示准确回执。
- 统计接口仍使用其独立的严格参数合同；修正多传 ID 和把 `config` 误读成 `settings` 的问题，开关受理即更新，统计队列调整在后台完成。
