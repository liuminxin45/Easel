# 设计说明 v2

新合同执行[写作要求](../写作要求.md#创作意图与设计说明-v2)。这是填写结构，不是已完成记录；所有依据、指纹与位置都从本轮冻结快照和实际成品取得。保留[风格权重表v1](风格权重表模板.md)原件及历史合同，不用新模板补造旧检查。

成品之外独立保存 `设计说明.json`。顶层使用 `schema_version:2`、`basis:"execution"`、`dimensions` 和 `responses`；本轮冻结的 `style_delivery_contract` 给出应回应的 `expected_basis_ids`。不要把模板示例ID、样例SHA或位置当成实际证据。

## 六项字段

| ID | 含义 | 可选intent |
| --- | --- | --- |
| title | 标题切入 | news 消息变化；change_use 变化与用途；value 读者价值；question 问题与真实反差 |
| text | 信息展开 | brief 简要；standard 标准；expanded 展开 |
| tone | 表达语气 | plain 平实；natural 自然；vivid 鲜活 |
| structure | 内容组织 | conclusion_first 结论先行；points_then_explain 要点后解释；process 过程叙事 |
| image | 配图表达 | scene 具象场景；diagram 信息图解；typographic 文字排版；scene_diagram 场景与图解 |
| style | 画面信息量 | focused 聚焦；balanced 适中；rich 丰富 |

`dimensions` 六项各出现一次。适用项的 `intent` 与本轮冻结模式一致，不能因实际没做到而改写目标。每项写 `applicable`、`outcome`、`reason`、`basis_ids`、`deliverables`；适用项引用本轮真实依据ID。

`outcome` 使用 applied、partial、not_applied、deferred、not_applicable。applied／partial 必须给实际交付引用；其余情况说明真实原因。不适用项设 `applicable:false`、`intent:null`、`outcome:"not_applicable"`、空 `deliverables`，不填虚构位置。只生成配图、锁定用户标题／正文、固定母版等按本轮实际范围判断。

`responses` 每个本轮必需依据ID只出现一次，包含 `basis_id`、`dimension`、`outcome`、`reason`、`deliverables`；依据为当前批注时加真实 `annotation_id`。不用“已处理”替代具体改变，也不加入本轮没有的ID。

## 原文与画面位置

每个 `deliverables` 引用包含 `artifact_name`、`sha256`、`location` 和真实锚点。`artifact_name` 与本轮交付文件名完全一致；SHA为实际完整文件的64位小写SHA-256。`location` 是供人阅读的标签，不能单独证明位置存在。

文字引用的结构如下。示例仅说明字段，不是可直接提交的证据：

```json
{
  "artifact_name": "本轮实际文案文件名",
  "sha256": "填写实际文件的64位小写SHA-256",
  "location": "填写可读的真实段落位置",
  "anchor": {"type": "text", "start": 0, "end": 4, "quote": "实际原字"}
}
```

`start/end` 是从0开始、左闭右开的Unicode码点位置；先按UTF-8解码，保留CRLF、空格和换行，不做Unicode或空白规范化。`raw[start:end]` 必须精确等于 `quote`。这不是UTF-8字节位置或JavaScript UTF-16长度。也可不提供坐标、只提供全文唯一的顶层 `quote`，由程序核出真实位置；出现多次时必须给准确坐标。HTML等文件的原字坐标只证明对应源码位置，不能替代实际排版查看。

图片引用结构如下，示例区域不代表本轮真实采用位置：

```json
{
  "artifact_name": "本轮实际图片文件名",
  "sha256": "填写实际文件的64位小写SHA-256",
  "location": "填写画面中的真实区域",
  "anchor": {"type": "region", "x": 0.1, "y": 0.2, "width": 0.5, "height": 0.4}
}
```

坐标是相对整张图片宽高的0–1归一化值，以左上角为原点；使用有限数值，不接受布尔值、NaN、Infinity。宽高大于0，`x+width`、`y+height` 不超过1。区域核验只证明引用区域存在，画面是否符合选择和反馈仍需独立查看实际图片。

## 交付核对

- 实际读取本轮 `creative_snapshot_file`／审阅快照，确认版本、原字、策略、必需依据及不适用范围。
- 按真实字节计算SHA，文字原字坐标和图片区域都能被复查，全部必需ID唯一回应。
- 制作方自述、程序结果、独立成品观察及用户决定分别保留；未核验写明未核验，不把程序通过当审美批准。
- 仅缺元数据时补说明，不重画；确需内部修正时另存并沿同一冻结依据最多一次，不混入新反馈。
- 说明不进入读者正文或图片，不扩大采纳、归档、同步或发布权限。未采纳贴图继续遵守临时目录边界。
