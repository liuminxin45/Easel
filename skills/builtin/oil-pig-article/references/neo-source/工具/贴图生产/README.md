# 贴图生产工具

实际可运行的本地检查器与 HTML 图片导出器。Agent 根据主题写稿、核查来源、在内置浏览器截原帖及完成实测；本工具不调用模型、不登录社交平台、不发布，也不判定用户认可。

成品规则来自 [贴图要求](../../规范/公众号贴图写作要求.md) 和 [图片要求](../../规范/图片制作要求.md)。字符上限与默认尺寸运行时读取对应规范表格，不维护另一份数值配置。修改表格接口时同步检查工具；无法读取时明确报错，不回退旧规则。

新版本还须完成[标题与配图反馈检查](../内容工作流/README.md#标题与配图反馈检查)：草稿包与`创作检查.json`同层，填写实际`work_id/version`和`creative_review`，新制作的render/check加`--require-creative-review`。制作前检查标题取舍、历史案例与逐图分工，交付前核对成品、原图和手机预览的绑定；主观判断仍由Agent完成。未声明新接口的历史包保持原行为，不补造历史检查。

## 安装和执行

需要 Node.js 22 或更新版本。在本目录执行：

```powershell
npm ci
npm run setup:browser
npm test
```

浏览器安装为本机依赖，不入 Git。另一台电脑重复安装，不依赖本机缓存路径。在项目根目录执行：

```powershell
node 工具/贴图生产/cli.mjs render --manifest "内容/标题目录/草稿包-v0.1.json"
node 工具/贴图生产/cli.mjs check --manifest "内容/标题目录/草稿包-v0.1.json"
```

`render` 先检查材料并验证整批页面，再保存 PNG；拒绝覆盖现有图片。`check` 检查最终图片、配文及引用的材料。只有原帖截图或纯文字时无需执行 render。标准输出为 JSON 报告，退出码 0=通过、1=检查或运行失败、2=错误调用。报告须由 Agent 按需归入本篇或 .runtime/，工具不写无关日志。

## 草稿包接口 v1

草稿包放在单篇目录。以下是 HTML 图解的格式示例，示例文件名由 Agent 在实际创作时生成，不是现存内容：

```json
{
  "schema_version": 1,
  "title": "先展示证据再解释判断",
  "kind": "explainer",
  "status": "草稿",
  "review": "待用户评审",
  "body_file": "配文-草稿-v0.1.txt",
  "pages": [
    {
      "html": "素材/图解-v0.1.html",
      "selector": "[data-poster-page=\"01\"]",
      "output": "素材/图解-01-v0.1.png"
    }
  ],
  "assets": []
}
```

- `kind`：news、tool、opinion、explainer、text。仅纯文字可无 pages/assets。多页按 pages 数组顺序导出；原帖与 HTML 混用的最终阅读顺序写在本篇图片编排说明中，不按文件名猜测。
- `body_file`：只有正文配文的 UTF-8 文件，不含标题、计数、制作注释。计数按 Unicode 码点，计入标点、数字、英文、空格、标签和可见链接，忽略换行及开头 BOM。Markdown 源中的格式符也会被保守计入，建议用纯文本配文。
- `pages`：html、唯一 selector、output；可显式指定 width、height 覆盖规范默认尺寸。输入 .html、输出 .png。一个 HTML 可包含多个独立页面，用不同 selector 导出。
- `assets`：每项 kind 为 image、post-screenshot 或 run-screenshot，file 引用现存 PNG/JPEG；检查实际尺寸、编码、扩展名并报告 SHA-256。代码原生图形可直接写进 HTML，不需创建位图素材。
- `sources_file`：非空来源核查文件。新闻、工具及使用原帖截图的稿件必须提供。其他内容有外部事实时也应提供，是否有外部事实需人工核查。
- 原帖素材另有 source_url、author、published_at、captured_at、scope、context_file，均为非空字符串。source_url 填原帖永久链接；published_at 不可见时写“页面未显示”，不推测。context_file 引用非空上下文原图。截图必须由内置浏览器实际取得；机器只检查记录结构，不独立证明来源真实性。
- 运行截图另有 record，指向非空实测记录。工具功能介绍可凭可信来源制作，不强制提供test。需要实测支撑的主张使用 `test: {"required":true,"status":"completed","record":"实测记录-v0.1.md","outputs":["素材/实际输出-v0.1.txt"]}`；required=true而未完成、或声明completed但缺记录/真实输出时检查失败。旧包的completed状态仍校验实测材料。是否需要实测、事实是否超出来源及结果是否值得入图由Agent依据规范核验，程序不自动判断正文语义。

所有文件路径相对草稿包目录，拒绝越出该目录、经链接逃逸、重复输出和覆盖旧图。绝对项目位置可改变，包内相对引用继续有效。

## 导出与检查边界

HTML 导出仅加载本地材料，阻止 HTTP(S) 请求。先保存需要的外部素材并使用本地相对路径；避免远程字体。等待字体及图片加载，检查唯一页面、尺寸、缺图、运行错误、元素与文字溢出，再截图。整批失败不留下此前页面的半成品；写出时只撤销本次新建输出。

模板见 [贴图页面模板](../../规范/模板/贴图页面模板.html)。测试构造材料归入忽略的 .runtime/，不写到内容/。可读性、语义、图片是否拉伸、来源是否支持结论及裁切是否误导仍须逐图人工查看。检测不能保证所有 CSS 视觉问题都被识别。

本工具实现的是 Agent 的确定性辅助步骤，不是独立输入主题即可无人值守产出的服务。完整入口见 [手动流程](../../自动化/方案/贴图草稿手动生产流程.md)。

贴图完成后必须展示并询问用户是否采纳。未采纳图片/配文/HTML放.runtime，采纳才转存成品档案；不采纳只长期保留价值过程。最终决策后调用共享[采纳与同步工具](../内容工作流/README.md#当前采纳收尾210)自动提交推送本次范围；检查器本身仍不判定用户认可。
