# 贴图生产操作

所有项目路径相对于本技能所在项目根目录。成品要求只维护在规范/公众号贴图写作要求.md、规范/图片制作要求.md；本文件是操作适配，不另设字数、定位或发布权限。

## 从主题开始

1. 读取当前贴图、图片与存档规范。工具题材另读效率工具分享要求。检查内容索引；续作先读对应内容档案.md、进度.md、反馈.md和最新修改记录，不继续此前未采用示例。
2. 在一个标题目录记录创作需求、暂定观点与选角度理由，区分用户观点和助手判断。缺少经历不编造；有明确主题直接生产，不强制先给角度让用户选择。
3. 新闻核查直接来源；收到 aihot 等聚合新闻链接时，主动打开条目并跟随其来源、引用帖和线程链接找到原始材料，不要求用户另行提供已可追溯的原帖。博主材料按下节操作。工具按本篇主张判断是否需要实测：功能介绍可依据可信来源，实际效果、亲测推荐和验证教程须有对应实测；不能把未测写成亲测。
4. 按图片规范先检查原始来源的现成图片、附件、README与assets、表格和流程，记录取得范围及来源对应。主视觉优先序、真实素材作用和工具选择执行[图片规范](../../../../规范/图片制作要求.md#具象小猪场景优先2026-10-23)，逐图确定任务、信息增量、证据与阅读顺序。做过的实测只有结果增加读者理解或判断所需的信息时才入图，内部验证不自动变成一页内容。配文按[共同写作方向](../../../../规范/写作要求.md#用户任务与技术解释2026-10-23)说明具体变化与用途，只保留影响理解或使用的条件，自然结束。

新版本在生图/排版前按[标题与配图反馈检查](../../../../规范/写作要求.md#标题与配图的反馈检查)prepare本包同层`创作检查.json`，填写本篇标题比较与逐图分工，阅读案例原话和边界，绑定实际提示词/身份参考并通过plan。草稿包新增`creative_review:"创作检查.json"`，新制作render/check均加`--require-creative-review`。生成后实际查看整图/手机预览，绑定最终文件和查看记录，通过delivery才交付。命令与字段见[工具说明](../../../../工具/内容工作流/README.md#标题与配图反馈检查)。固定Tech Pulse按新冻结合同的接入执行，不强迫改标题或母版；旧包复查不补造新检查。

用户要求 taste-skill 与生图技能搭配时，在生成前读取并应用两技能，按图片规范形成具体设计方案，写入实际生图提示词后执行；保存方案、提示词、原件、参考及修改记录，生成后再核对文字和视觉结果。

新自制贴图按图片规范的固定品牌角色与风格要求，在生成前调用taste-skill参与UI、布局、字体和排版设计。使用小猪侠时读取项目内角色规范并实际查看已认可正面与三视图，复用资产或将对应PNG作为生图身份参考；画面可随主题变化，角色身份保持，生成后核对母版。规则仅引用图片规范，不在本操作文件另建角色风格。

GIF制作按[图片规范的动图默认技能与角色动作](../../../../规范/图片制作要求.md#动图默认技能与角色动作2026-10-20)接入已安装的GIF Sticker Studio与Remotion技能：先设计连续动作，再真实合成、预览并检查；本操作入口只引用唯一规范，不另建动图规则。

动图专项检查保留；`creative_review.py`分别运行plan/delivery并明确`--expected-work-id/--expected-version/--expected-title/--expect-file`，将实际GIF/WebP、配文和独立手机预览绑定。通用HTML导出器仍只识别PNG/JPEG，不用它替代帧序、时长和回环检查。命令见工作流工具的动图说明。

## 原帖与运行截图

联网定位时使用当前可用的检索技能与平台路由；读取能力不能代替在内置浏览器核对原帖。首次浏览器操作读取当前浏览器工具文档和截图文档，使用 cua_repl 的内置浏览器绑定，不使用命令行浏览器冒充已在内置浏览器检查。

打开实际永久链接，检查账号、正文与时间，展开折叠内容；从最新页面状态定位帖子区域。保存上下文截图与区域截图，记录截取范围和来源。使用浏览器截图接口的 clip 参数直接捕获真实区域；不修改第三方 DOM。若内容跨屏，按实际阅读顺序分别截图。保存接口返回的原始字节，核对编码和扩展名；不能只留聊天图或缓存。

精裁前先让目标完整进入实际可见区域，再读取最新边界；页面有内部滚动时不能只依赖window.scrollY。屏外部分可能被截图接口填成空白，截图后必须目视核对，不能把坐标有效等同于素材完整。

英文 X 原帖检查页面是否提供官方翻译入口，按图片规范执行翻译截图；没有入口时记录当前登录状态和阻塞，需要用户完成登录时明确指出，并继续配文及独立图解制作。不能默认用本地HTML替换原帖中文：用户已否定这一效果。核对平台翻译、作者、日期和活动条件，保留英文原件；截图与解读分开，不修改第三方页面。

用户明确不登录并授权替换正文时，停止登录接续；使用本地HTML保留真实截图版式和附件，仅替换正文并截图，按图片规范标记中文译文和记录采用范围，不返回被否定的重新造卡方式。

登录、页面不可达、删除或截图保存失败时写明哪一步未完成。不要把检索摘要、二手截图、HTML 仿制当作已取得的原帖截图。需用户协助时提出具体阻塞并保持待办。

工具运行截图绑定实际输入和输出。CLI 没有可捕获的原生界面时，可以展示实际输出文件；日志转排按图片规范明确标注，不冒充原生终端。

## 使用本地工具

阅读工具/贴图生产/README.md。首次在该目录执行 npm ci 和 npm run setup:browser，后续直接复用依赖。复制规范/模板/贴图页面模板.html 到本篇素材/的版本文件，修改内容与版式；模板示例不等于认可样本。

使用一份版本草稿包 JSON 关联标题、仅包含配文的 UTF-8 文件、来源、实测与素材；格式见工具说明。HTML 每页有唯一 selector，输出使用新版本文件名。原帖与实测截图可直接交付，无需为凑图再次排版；纯文字明确 kind=text。

从项目根目录运行：

```powershell
node 工具/贴图生产/cli.mjs render --manifest ".runtime/贴图待采纳/标题目录/v0.1/草稿包.json" --require-creative-review
node 工具/贴图生产/cli.mjs check --manifest ".runtime/贴图待采纳/标题目录/v0.1/草稿包.json" --require-creative-review
```

根据错误修正；不是每篇都需要 render。导出器仅访问本地文件，远程图片、字体、样式须先合法取得并归入素材/或改为系统字体。事实与素材内容的正确性由 Agent 核查，工具只检查文件、元数据、计数与版面。

## 交付与接续

交付本版候选时附[风格权重简表](../../../../规范/写作要求.md#交付后的风格权重表)，说明标题、文风、结构与图文呈现的实际参考和取舍；表放在产品之外，认可及缓存边界仍按下文收尾。

导出后逐张查看实际图片与手机尺度阅读效果，按图片与贴图规范检查首图完整标题、图上的无用说明及配文、截图和图解一致性。材料和有价值的检查报告保存到本篇，临时输出放 .runtime/。用户指导完整记录与风格学习执行写作及存档规范；更新内容档案.md、进度.md，记录真实确认状态、当前文件与阻塞项。

聊天按阅读顺序内嵌实际图片（本地图片使用绝对路径），再依照内容总规格和贴图规范分别交付可复制标题与正文；交付前核对标题与首图及草稿包一致，不能以图内标题替代单独标题。另给字数、来源或实测结论、待确认项及文件入口。输出文件存在不代表被用户采用。只重做受反馈影响的部分，改核心观点时重查关联证据，历史版本不覆盖。

## 采纳与自动同步收尾

执行规范/存档规范.md“贴图先采纳，再归档与同步”。从制作开始把本轮图片、配文、HTML、实际提示词及中间输入放.runtime/贴图待采纳/标题/版本；内容/标题保留完整沟通、意见、用户参考原件、有价值来源核查和进度。上文素材/草稿包位置仅描述采用后的长期归属，生成时不能把候选直接归档。

核查与check通过、逐图目视完成后，保存候选包内程序检查.json和目视检查.md，展示整组实际图片与配文，明确询问用户是否采纳。可用request_user_input_async提出“采纳/不采纳/继续修改”，答复前不收尾。按用户真实答复保存全文，不能将局部风格认可或历史许可替代本期采纳。

采纳用工具/内容工作流/poster_review.py decide将完整候选转入本篇产物/版本；不采纳只保留有价值过程并移除本轮临时候选；继续修改保留临时材料接续。生成逐个文件的同步范围JSON，含决策、采纳原话路径和SHA、remote/remote_url/branch及files列表；否决时process_only=true，用户原附件另列process_attachments及SHA。运行同工具sync一次完成限定提交、推送和远端核对。只列本篇和必要规则/工具，禁止git add .或all。同步授权已存在，不重复问；失败保留答复与状态，只重试同步。采纳和同步不代表发布。

命令参数和固定流程例子见工具/内容工作流/README.md的采纳收尾段。默认文章没有新加贴图采纳门槛。
