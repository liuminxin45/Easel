# 通用主题文章操作

适用“写文章：主题”、完整长文与重写。固定栏目先读对应工作流，不将三源结构套入开放题材。

1. 读写作要求、内容总规格、存档规范；续作读档案、进度、完整反馈与最近修改记录。按 [文章学习](文章学习.md) 从样本索引选择相关类型笔记、少量参考及个人原始材料，反馈为空时查实际讨论来源。确定读者、核心问题、真实材料与事实边界。完整稿已获请求时直接完成，不为固定预览中途停下。
2. 取材核查，区分亲历、原作者陈述和暂定解释；保存完整指导和直接来源。经历不编造，工具题材按相应要求及内容主张选择证据，不能把功能资料写成亲测结果。
3. 提纲围绕本篇问题，按材料选择新闻解读、工程方法分享、工程复盘、个人思考、工具体验等结构，不固定栏目或篇幅。通常试用一两项适合的写法，在本篇制作／修改记录说明样本、方法及选择理由；借鉴依据不放进读者正文。
   新版本按[标题与配图反馈检查](../../../../规范/写作要求.md#标题与配图的反馈检查)建立与正文同层的`创作检查.json`，填写标题比较及实际配图分工，完成历史案例比较和plan绑定再制作；无图文章用profile=none说明理由，固定标题按原话/冻结约定保留。具体字段与命令见[工具说明](../../../../工具/内容工作流/README.md#标题与配图反馈检查)。
4. 写正文并检查事实、信息增量、观点依据、语气与反例。重写保留核心问题和经历，历史稿及发布快照不覆盖。
5. 公众号 HTML 读取排版要求和模板，正文样式内联，标题置复制区外，来源对应、图片不拉伸。不把贴图字号用于文章，配图按需要制作。
6. 按[文章批注操作](文章批注.md)为审阅HTML接入选中批注和本机自动保存，再检查正文与HTML对应、来源、手机断行和素材；批注层不进入复制区。浏览器预览与公众号后台粘贴分别报告，不将本地HTML说成已验证粘贴。收到批注改稿时按该操作保留每轮、归档后再清空。
7. 保存正文、HTML、来源及制作记录，更新档案和进度。按[风格权重要求](../../../../规范/写作要求.md#交付后的风格权重表)附本版简表与依据，供用户调整。交付实际文件与边界，待用户评审；发布、提交、推送按明确指令。
   实际查看配图完整/手机预览后绑定delivery；新`文章交付.json`增加`work_id`、`version`、`html_file`、`images`（正文实际配图文件数组，无图为空）及`creative_review:"创作检查.json"`。最后调用`article-check.mjs 正文HTML 预览目录 --article-manifest 文章交付.json --require-creative-review`或独立检查器验证本版。初次生成本地预览可先用原两参数，不把版面检查当完整创作验收。正文/HTML/配图变化须重新检查；product实测要求和文章交付前归档不被本检查替代，旧稿不补造新记录。

后续有实质反馈时，按文章学习操作保留完整原话和修改前后，并更新相关类型笔记与索引。候选试用不等于个人认可；明确新要求及时按范围处理，不为凑够样本而延迟。
