# 会话断线后状态收敛

## 目标与边界

用户批准三批修复，全部验证后一起提交自有 fork 并部署。连接恢复后继续同一会话；不重新发送已受理指令，不回退私有能力。Tailscale 仅暴露网络。复用 Easel ChatPage、状态卡、事件续流和原生执行器；业务核对集中在 PC-03 私有层。

## 调查证据

按 ai-engineering-radar 链接定位的两轮在工作台 SQLite、持久 SSE 日志和 Codex rollout 中均已完成。隔离注入 EOF 后半开续流时，前端保留 running/pending，未发起回执读取。流读取没有静默超时，备用恢复被 owner 阻挡，历史完成与本地 pending 缺少统一核对。真实 unknown 又没有原生终态收敛出口。

## 实施批次

1. 统一准确回合回执的终态收敛；完成、停止、失败恢复输入，保留后写草稿和附件，晚到回调不能复活旧回合。
2. 私有看门狗、前台/在线/重登录核对；只重订阅 GET。对失去执行所有权的 Codex 回合，以准确原生线程/回合的持久终态证据核对，不猜测、不重跑。
3. 复用状态卡附着当前回合，短断线静默、持续故障明确；增加半开、漏 done、后端重启、暂停竞态、跨设备/重登录及旧回执测试，记录有界脱敏状态诊断。

## 验收

- 服务器终态必须解除准确旧回合锁，不清空后写输入；活动/未知回合不能误解锁。
- 原生证据必须匹配线程及回合；缺失、损坏、运行中或身份不符仍 unknown。
- 不创建第二个执行器、模型调用或发布/采纳授权；不会自动重发。
- 前端检查、原生与官方构建、相关 Python/前端测试、隔离移动浏览器旅程、架构/技能检查。
- 自有 origin/main 推送 SHA 核验；冻结准确前后端后空闲部署，核对活动版本和健康入口。

## 进度与证据

三批源码已实现。核对逻辑还覆盖历史读取失败时的旧 pending：已验证的终态覆盖准确旧锁，并从回执补齐最终回复，恢复后写输入。原生核对只接受匹配线程、回合、cwd 的有界完整终态记录，CAS 更新原记录后清理同一 pending；产物接收沿原幂等 hook，不增加执行器。共通源码只加3行可选活动回调。

已通过：73项后端会话/受理/超时/原生回执测试，62项架构与技能策略/命令测试，67项前端恢复/暂停/草稿/跨设备竞态测试；私有检查、私有构建、原 Easel 独立构建与私有登记门禁通过。测试夹具改用当前原生聊天冻结合同，未恢复已退役讨论计划；官方差异检查补登记已上线学习技能与已审阅名称映射准确 blob，没有扩大目录豁免。

实际日志位于 `.local/workbench-validation/chat-reconnect-{release-tests,architecture,batch3-frontend,check,build,official-build}.log`。完整冻结浏览器故障验收、推送 SHA、准入和活动配对将在同前缀 `candidate/acceptance/deploy` 证据记录核验。当前阶段尚未切换正式版本；不将合成执行冒称实体手机或真实模型验收。
