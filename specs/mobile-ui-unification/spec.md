# 移动端全页与弹窗交互统一优化

Spec: mobile-ui-unification

## 用户目标与保留行为

逐页核查移动页面及弹窗，优先复用 Easel 原生组件，减少简陋提示与冗余控件。
修复后验证，提交推送自有 fork，再部署上线。

以官方基线 5a597e5 和现有 App/页面/组件/token 为准，不建立第二套视觉体系。
保留原始反馈、准确版本、草稿附件、未知回执身份及授权；反馈、修改、采纳不自动扩大制作或发布范围。
独立后端架构改造在另一聊天进行，本轮不将其未完成文件纳入UI交付。

## 已核实的问题与实现范围

- 新闻原文页缺少已存在的 page-scroll 布局；直接复用原容器，并用长正文证明底部可达。
- 中断版本同时出现父版本状态与产物状态；每版只保留一处 TaskStatus，继续动作仍核对准确版本。
- 技能详情、发布确认和差异记录形成三层弹窗；改为同一 Modal 内切换，保留返回、输入与批准边界。
- 技能页重复基座/源码等工程说明；恢复简洁任务说明，保留真实故障与禁用原因。
- 部分原生控件触控区域过小；仅用宿主移动几何适配放大目标，不改共通外观或官方源码。
- 手动发布/复盘日期要求手打 ISO；使用原生日期时间输入，集中转换，未编辑不重写原值，未知仍留空。
