“Easel 之外”不能简单理解为 `easel/` 目录以外的所有文件。

    profiles/            创作画像、准确修订、技能 pins
    collection/          来源、采集任务、新闻与调度规则
    evidence/            证据索引、参考分析与按需经验候选

不是为每个域预先创建空目录、BaseService、通用 Repository 或事件总线。只有实际迁移到的域才建包；`application/` 只处理已有跨域用例，不创建新的制作引擎或执行状态机。旧 `application.py` 在需要引入同名包时必须先显式消除文件/包同名冲突，保持 `create_app` 导出和调用者合同。

前端保留已有 `ui/core/platform` 三个方向，仅将业务调用与平台副作用归位。现在的 core 含 React hooks，因此不能把整个 core 宣称为纯业务内核；必要时将 hooks 归入 ui，纯客户端协议留在 core，避免大规模重命名或重做页面。

## 四、依赖与状态合同

1. `contracts` 为叶子模块，不导入 FastAPI、SQLite、业务服务、文件执行或进程启动。
2. HTTP 将输入转成现有用例调用并投影结果，不决定技能规则、重试、采纳或发布事实。
3. 域服务不导入 HTTP、启动装配或兼容实现。跨域写入通过明确用例协调；跨域只读聚合使用查询投影，不让仓库成为隐式业务调度器。
4. 具体 SQLite、文件、进程和 Easel 接入由装配入口注入。需要的接口按实际边界定义；复用已有公共类型，不为形式上的解耦复制一套引擎协议。
5. 多域原子操作共享同一个当前连接/事务。repository 不擅自新建连接或提交事务；取消时继续保持现有锁释放和在途线程收敛合同。
6. 兼容导出只委托唯一实现，不复制函数、不保留两个注册表、不通过兼容路径反向接入新业务。旧入口是否可移除，要有调用和历史引用的核对记录。
7. 使用 `AppServices` 或具体构造参数替代逐步新增的 `box.xxx` 隐式挂载；只为正在拆出的依赖增加明确参数，不一次改写所有服务构造。
8. 文件读取与签名校验保持现有实现的字节和编码语义。同名 `sha/digest/packed/text` 不保证等价，不做自动统一或全局替换。

| 状态/能力 | 唯一权威与迁移约束 |
|---|---|
| 会话、回合、原生绑定和 SSE 事件 | 保持服务器台账与原 Easel `_sessions` 绑定；重连只是读取，不发起第二个模型回合 |
| 制作受理与作品登记 | 保持同一事务；忙碌拒绝不产生孤立任务；受理后的配置和技能不可重新解析 |
| 作品、父版、反馈、采纳 | 保持准确作品/版本/操作身份；同一对话可关联多个作品；保留原始意见 |
| 技能与画像 | 当前项目 SKILL.md、不可变版本和本轮冻结副本各有职责；不以当前磁盘覆盖旧快照 |
| 平台账号与交付 | 实际账号、创作画像、执行身份分开；制作与 Full access 不新增发布授权 |
| 配置与安装 | 配置修订仅供后续新会话；沿用同一持久安装队列与固定运行环境 |
| 下载 | 公共 DownloadManager → 私有 resolver → 原鉴权与准确文件处理器；不暴露裸 Cookie 下载、不宣称已在实体设备保存 |
| unknown 与旧任务 | 保留原身份和准确回执；不将重构/重启当成重新发送的授权 |

### 第一批具体落点

- 提取 `native_api.py` 中纯媒体路径分类为 `contracts/media_paths.py`；`native_api` 与下载校验共同使用。既有函数入口可薄导出兼容。
- 从 `toolbox_store` 提取实际被跨域使用的纯校验函数，明确其历史合法值、错误消息和 JSON/哈希语义；原位置暂保留委托。
- 下载业务只获得现有文件读取/HEAD 核对端口；不为下载新建文件注册表或独立文件数据库。保持先检查目标、再签发能力的顺序。
- 将 `/api/downloads` 与 `/media/downloads` 的 HTTP 解析逐步移到专用私有路由模块；仍调用原文件处理器，首批不重写 ZIP/原件读取。
- 在现有架构检查中加入新包依赖方向与反例检测。断言实际越层行为，不通过扩大白名单或忽略旧模块来制造通过。

第一批完成以两个目标为准：下载校验不再导入 API 路由模块；业务代码不再为取基础校验函数导入整个 Toolbox。无需预先拆完 138 个模块。

## 六、兼容、事务与发布风险

迁移前每一片都检查：

- Python 模块字符串、角色启动参数、外部 CLI、序列化记录或冻结文本中的旧路径。已冻结文本不改写，用薄兼容入口承接；不能把历史路径机械替换为新包名。
- `Path(__file__)`、`with_name`、相邻 JS/JSON、来源配置及 vendor 资源。迁移后使用明确项目/资源根，验证冻结包和干净检出；不靠开发目录中偶然存在的文件通过。
- 表初始化的事务和顺序、同名历史表的真正写入者。第一阶段不改表名、ID、状态枚举、指纹算法或数据库结构；结构升级如确有需要另作单独方案。
- 凭据、安装路径、OS 锁以及完整进程创建时间。源码挪动不授予新的账号操作或环境修改权限。

不同时运行新旧业务写入者。前后对照在隔离 TEMP 数据上分别执行；不能用双写生产库来证明等价。确定性响应、文件字节、状态迁移、调用次数和原生回执逐项比较；时间/随机 ID 如需归一化须先列出允许差异字段，不忽略业务身份或错误状态。
