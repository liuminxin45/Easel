# 项目技能准确字节与发布准入修复

## 目标与原因

用户从热点制作贴图时得到“此项目技能尚不可调用”。生产库已发布的8个私有技能均因
资源字节与当前源码不一致而不可调用：Windows Git core.autocrlf=true 把已冻结LF或混合
换行转换成CRLF，文本未变化但SHA256变化。此前发布仅核对源码自身指纹，未核对生产库。

恢复已发布准确字节，不关闭校验、不修改历史版本或默认pin、不重发失败/未知请求。
官方页面与执行链路保持；只修复私有技能保存和发布准入，推送自有fork main并部署。

## 实施与验收

- 私有8个builtin目录及shared/workbench使用Git -text，保存准确原字节；官方技能不受影响。
- 从当前已发布blob恢复仅存在换行差异的文件，恢复前验证SHA与文本等价，保留原件备份。
- 冻结与切换前调用同一matches_source，分别核对实际DB已发布技能与工作区/不可变候选。
- 新增真实Git autocrlf检出、混合换行、拒绝资源漂移/未完成发布及生产库只读回归。
- 自有fork新增Windows/Linux × autocrlf true/false四组合CI，核对29份当前执行资源的独立准确字节
  lock与Git属性，并跑发布/准入回归。lock只供CI、不参与运行时能力发现、不自动更新历史发布。
- pre-push同步运行准确字节检查；远端Actions当前返回repository disabled，保留明确未运行状态。
- TEMP复现热点→贴图方案/冻结受理；真实线上只验证可调用状态和方案，不发送模型任务。
